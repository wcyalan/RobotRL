# Phase 3：人形机器人强化学习

本目录接续 `phase2_isaaclab/` 的 Go2 项目。这里的 **phase3 是代码目录编号**，对应仓库路线中的“阶段5：人形机器人仿真行走”，不改动已有实验编号。

目标是自己完成一个人形机器人平地运动项目：理解任务与控制链路，复现官方PPO基线，验证站立、前进、转向与启停，完成最小鲁棒性对照和模型导出。优先选Unitree G1；只有现有后端确实不支持时，才考虑H1或单独建立兼容环境。首轮不加入跑跳、起身、搬运、语言指令、VLA或世界模型。

**当前状态：学习计划与入门笔记已建立，尚未验证G1运行环境，也未启动训练。** 下文是准备执行的方案，不是已完成结果。

## 学习与实践顺序

### 1. 建立双足运动的直觉

1. 阅读笔记1，先理解机身、关节、足底接触三者的关系。
2. 画出“双脚支撑→左脚支撑→双脚支撑→右脚支撑”的简图，标出支撑腿与摆动腿。
3. 用自己的话解释：机器人身体前倾时，为什么有时需要向前迈一步，而不是只把上身拉直。
4. 区分质心投影、压力中心和落脚点；知道本文倒立摆模型的假设，不把简化公式当成完整G1控制器。

完成标准：能解释为什么停止也需要一段平衡调整过程，为什么“质心投影始终在双脚之间”不是所有动态步态的必要条件。

### 2. 核对现有镜像中的任务和资产

先做只读核查，再做最小仿真。Go2可运行只说明现有kitless/Newton链路可用，不证明同镜像中的G1资产和任务可用。

1. 记录实际镜像digest、Isaac Lab版本/源码版本、物理后端、RSL-RL与PyTorch版本。
2. 在**实际运行容器**中列出注册任务，查找G1平地速度跟踪任务；定位其环境配置、agent配置和资产配置。登录节点的另一份源码只能作参考。
3. 核对资产能否读取：文件路径、关节名、碰撞形状、质量/惯量、足部与终止检测用到的body名称。
4. 先用1–4个环境完成reset和有限步进，确认观测、奖励有限，接触与自动reset不报错。
5. 使用零策略动作时，先查清它代表默认关节目标、零力矩还是其他含义；零动作测试不要求机器人必然站稳。
6. 没有graphics时延续Go2方式保存姿态并离线回放，明确这是运动学重放。当前未验证G1离线渲染资产，不提前承诺视频已可生成。

完成标准：确定一个实际可运行的任务、一个资产版本和一个后端。若失败，先定位任务注册、资产、执行器或后端问题，不靠延长训练解决。

官方文档中的命令示例为 `./isaaclab.sh -p scripts/environments/list_envs.py --keyword G1`；需要先确认固定镜像中脚本存在。不同文档版本可能列出带`-v0`、`-v1`或其他后缀的任务，不从网页名字推断当前容器的准确ID。见[官方环境列表](https://isaac-sim.github.io/IsaacLab/main/source/overview/environments.html)与[Newton训练环境说明](https://isaac-sim.github.io/IsaacLab/v2.3.2/source/experimental-features/newton-physics-integration/training-environments.html)。

### 3. 读懂任务，再运行训练

阅读笔记2、3，按实际配置填出以下内容，写进本目录的任务说明即可，不另建一套管理清单。

|需要确认|具体问题|
|机器人|总关节数、受控关节数、固定关节、手臂/腰是否控制、左右腿映射|
|观测|actor/critic各看什么，维数、顺序、坐标系、归一化、噪声、历史窗口|
|动作|关节目标/力矩/其他形式，缩放、默认姿态、裁剪在哪里生效|
|执行器|每组关节的刚度、阻尼、力矩/速度限制，后端如何执行|
|频率|物理步长、decimation、策略周期、后端内部子步|
|任务|指令范围和重采样周期、零指令比例、heading模式、curriculum|
|奖励|跟踪、姿态、步态、正则项分别是什么，是否乘时间步长|
|终止|摔倒判定用什么，哪些body允许接触，timeout如何处理|
|训练|PPO配置、并行环境数、rollout长度、训练迭代、归一化和checkpoint规则|

完成标准：能从一个策略输出解释到关节目标、执行器力矩和下一步观测；能指出至少三个“不能直接复制Go2”的数值。

### 4. 短训练验证链路

1. 采用选定任务的官方奖励、网络、PPO配置；先不改奖励和DR。
2. 以64–256个环境、10–20次更新作为**预检建议**。实际数值根据后端和资源确定，不能写成官方训练预算。
3. 检查观测/动作/奖励无NaN，梯度与loss有限，episode会正常结束，参数确实更新。
4. 保存checkpoint，退出训练，再用独立入口重新加载；不是仅在训练进程内调用同一个actor。
5. 保存少量轨迹，检查左右腿和上身是否运动、接触信号是否合理、自动reset是否混入前一回合。
6. 如存在观测归一化或历史缓冲，确认加载后统计量被冻结，reset时状态清空。

完成标准：训练、保存、加载、评估、回放的数据链路可靠。短训练的低回报或跌倒不自动判为实现失败，短暂站住也不等于学会行走。

### 5. 冻结评估协议，复现官方基线

1. 根据步骤3的实际指令范围，为零指令、低速前进、中速前进、左右转、启停确定数值和持续时间。
2. 在正式训练前固定评估seed、成功阈值、训练预算与模型选择规则。建议每条件32个完整回合；阈值不能照抄Go2，也不能看完结果再降低。
3. 第一条正式训练使用seed=0及任务配套预算。预算以实际配置的迭代数、环境数和rollout长度换算；不使用Go2的300轮作为默认值。
4. 保存学习曲线、终止原因和关键分项奖励。按预先固定的间隔评估，不因某次好看就停止记录。
5. 如需挑选checkpoint，用固定验证集；最终独立评估用未参与选模型的seed。若用最终checkpoint，也要预先说明。
6. 完成seed=0诊断后，保持配置和预算再训练seed=1。两个训练seed只提供初步重复性证据。

完成标准：两条完整训练结果都报告，能够解释同预算下的差异。若尚未形成稳定行走，先定位单一原因；不同时叠加奖励、DR和网络改动。

### 6. 行为验收与失败分析

|条件|要观察的行为|重点数据|
|零速度站立|是否持续踏步、扭腰、漂移|机身速度、转速、倾角、高度、足部接触|
|低/中速前进|是否拖脚、跳跃、长期屈膝|速度误差、支撑切换、触地时足部速度|
|左/右转|是否只会一侧、交叉步、自碰撞|角速度误差、平移漂移、左右脚接触|
|前进→停止→再启动|是否真正稳定后重新行走|停车延迟、稳定窗口、重启延迟、摔倒时刻|

1. 每个环境只统计首个完整回合，区分真正终止和时间截断；提前摔倒不能自动reset后拼接成成功回合。
2. 记录每组均值、分布、失败数、回合长度。条件包含多次指令变化时分别检查各段和过渡，不只报整局均值。
3. 保留预先选定的普通案例，以及由失败编号确定的异常案例。视频说明来源是仿真渲染还是姿态重放。
4. 先核对动作映射、配置和接触，再考虑训练不足。结果不好不是增加训练步数的充分理由。

完成标准：知道模型“会哪些、在哪些条件下不稳定”，而不只是给出一段成功视频。采用预先确定的预算；不反复跑到一次全过。若达到学习目标但剩余问题不再继续研究，可明确以已知限制收尾。

### 7. 最小鲁棒性对照

基础行走链路稳定后再做。不要把可能已含DR的官方基线直接叫作“无DR”。

1. 明确固定组和随机组；除预定质量/摩擦变化外，PPO、奖励、指令、初始化和训练预算保持一致。
2. 根据G1资产和后端选择范围，先验证实际质量与活动接触摩擦。Go2的0.8–1.2和0.5–1.5只是历史实验参数，不直接继承。
3. 每组seed=0、1，预先确定标称、范围内、范围外和固定扰动条件。明确扰动是力、冲量还是速度增量。
4. 逐训练seed比较；同一个模型的32个环境不能算32个训练seed。
5. 检查改善是否跨seed出现，保留负结果。仿真压力测试不等于真机迁移成功。

完成标准：能说明差异来自什么干预，哪些结论有数据支持。DR失败也是可完成的对照结果。

### 8. 导出与收尾

1. 固定两个seed最终使用的模型、配置、归一化状态和输入输出顺序。
2. 在同一批真实观测上比较原actor与导出actor；循环策略还要比较隐藏状态更新，不能只测单帧。
3. 独立推理入口不构造训练runner，重新验证reset、指令切换和动作执行。
4. 复用已冻结的行为协议，报告全部结果；工程链路通过与行为全部通过分别描述。
5. 更新本README为简洁结果入口，保留模型、必要代码、配置、数据和成功/失败视频。无需额外生成清理报告、归档恢复清单或一堆一次性check脚本。

完成标准：可以解释并复现“训练→保存→加载→评估→导出→回放”，明确局限，决定继续扩展还是结束学习项目。

## 文件与复用方式

现在只创建本README和三篇学习笔记。后续有实际代码时再创建 `training/`、`evaluation/`、`deployment/` 等目录，不先复制Go2全部文件，也不放空脚本占位。

实际结果放在仓库 `experiments/phase3_g1_baseline/run_001/` 等目录，按实验内容和顺序编号；**这些结果目录当前尚未创建**。如果最终选H1，名称随实际机器人修改。

可以复用Go2的任务打包方式、日志格式、模型哈希核验、冻结评估和轨迹回放思路。必须重新实现或核对关节映射、观测布局、执行器配置、资产、接触body、终止条件、归一化、动作输出和行为门槛。
