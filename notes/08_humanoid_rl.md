# 人形机器人：RL 任务与 PPO 训练

PPO仍然负责“根据采样数据更新策略”。人形任务变化的是状态、动作如何作用于机器人，以及奖励与终止如何定义。先把这个接口说清楚，比先增加训练时长更重要。

## 1. 任务：根据速度指令运动

一个常见的平地运动指令是：

```math
c_t=[v_{x,t}^{\ast},v_{y,t}^{\ast},\omega_{z,t}^{\ast}].
```

这里是目标前进速度、侧向速度和偏航角速度。通常还要明确它们是在机身坐标系还是世界坐标系。若任务使用目标朝向再转换为yaw rate，不能把heading模式与直接转速命令混为一谈。

策略根据观测和指令生成动作。训练时常通过不同指令让一个策略学习多种运动，而不是分别训练“左转网络”和“右转网络”。但网络能接收某个数值，不代表它在训练中充分见过这个数值和指令切换。

首轮问题不是“让机器人理解走路这句话”，而是“给定数值速度目标，让身体稳定地实现它”。语言理解、视觉导航和低层运动控制可以在以后组合。

## 2. 状态不等于观测

仿真完整状态可能包含所有物体状态、接触参数、质量和随机扰动。actor通常只能看到其中一部分。一个教学用观测形式是：

```math
o_t=[\omega_t^b,\hat{g}_t^b,c_t,q_t-q_0,\dot{q}_t,a_{t-1}].
```

可能还加入机身线速度、历史观测、步态相位或其他量。 **这不是G1的已核实观测表** ；具体布局必须读取选定任务。

|量|为什么可能有用|要核对什么|
|---|---|---|
|机身角速度|判断身体是否正在倾倒、转动|坐标系、量程、噪声|
|重力投影|提供倾斜信息|单位方向还是带重力大小的向量|
|关节角/角速度|知道腿和上身的姿态与运动|关节顺序、是否减默认角度|
|上一动作|反映控制历史，帮助限制变化|裁剪前还是实际执行动作|
|机身线速度|直接提供运动跟踪信息|actor是否真有该信息，部署如何估计|
|历史窗口|帮助推断未直接观测状态|长度、顺序、reset时如何清空|

重力投影能反映俯仰与横滚，但不能单独确定绕重力方向的绝对偏航角。速度估计也不应当作现实中免费可得的完美量。

如果critic能看到额外的真实速度、接触或随机参数，而actor看不到，就是一种非对称actor-critic设计。训练时可利用额外信息降低价值估计难度；部署actor时不能再偷偷依赖这些输入。是否采用这种设计必须读实际配置，不能从“人形”两个字推断。

## 3. 动作、关节目标、力矩不是同一个量

假设某任务采用关节位置偏移控制：

```math
q_t^{\ast}=q_0+s\odot a_t,
```

其中 $s$ 可以是每个关节不同的缩放系数， $\odot$ 表示逐元素相乘。执行器可能近似使用：

```math
\tau_t=K_p\odot(q_t^{\ast}-q_t)+K_d\odot(\dot{q}_t^{\ast}-\dot{q}_t).
```

这两式是教学模型。实际执行器还可能有限幅、速度相关力矩、延迟、隐式积分或其他机制。

例如某教学关节默认角度为0.2 rad，缩放为0.3 rad，actor输出0.5，则目标角度为0.35 rad。若当前角度为0.30 rad，刚度为40 N·m/rad，暂忽略阻尼，则比例项为2 N·m。三个数值分别是动作、目标位置和力矩，不能混用。

特别注意：

- 零策略动作可能表示默认姿态，不是零力矩。
- 动作裁剪、目标角限幅、力矩限幅是不同操作。
- 软关节限位惩罚是奖励项，不自动等于硬件安全夹紧。
- 不能把Go2的动作缩放0.25、刚度25或关节顺序直接套给G1。

## 4. 策略频率决定动作持续多久

如果物理步长为 $\Delta t_{\mathrm{sim}}$ ，每 $d$ 个物理步更新一次策略，则：

```math
\Delta t_{\mathrm{policy}}=d\Delta t_{\mathrm{sim}},\qquad
f_{\mathrm{policy}}=\frac{1}{d\Delta t_{\mathrm{sim}}}.
```

例如0.005秒与decimation=4对应50 Hz；这是频率换算示例，不是预先给G1指定的参数。改变频率会同时影响响应速度、动作变化惩罚、每秒采样数以及折扣的实际时间意义，因此它不是一个可以随便调整的加速开关。

## 5. 奖励：运动目标与运动质量的取舍

用三类理解奖励比较容易：

|类别|例子|可能带来的问题|
|---|---|---|
|任务目标|线速度、转速跟踪|只追速度可能不保证姿态自然|
|行为塑形|躯干直立、足部离地、适当接触节奏|过强可能限制有效恢复动作|
|正则与约束代价|力矩、关节速度、动作变化、限位、自碰撞|过强可能让策略宁可不动|

举例，速度跟踪奖励可采用：

```math
r_t^v=\exp\left(-\frac{\|v_t^{\ast}-v_t\|^2}{\sigma_v^2}\right).
```

这是常见设计形式的例子，需核对实际任务比较的是哪些速度分量、是否使用同一坐标系。误差越小奖励越大；当误差已很大时，指数奖励可能非常接近零。

动作平滑代价的例子为：

```math
c_t^a=\|a_t-a_{t-1}\|^2.
```

总奖励可组合为：

```math
r_t=w_vr_t^v+w_\omega r_t^\omega-w_ac_t^a-w_\tau\|\tau_t\|^2+\cdots.
```

权重大小不能脱离各项原始数值和时间积分方式比较。还要检查管理器是否再乘策略步长；同一个配置数字在不同频率下可能不具有相同的实际作用。

Go2中新增停车偏航惩罚后，其他运动也退化了。这提醒我们：各行为共享策略参数，即使一个奖励只在零指令生效，也不能保证对非零指令行为完全没有间接影响。

首轮使用官方奖励并先读懂它。出现问题时先看分项奖励与行为数据，再提出单项修改；不要一开始堆叠多个“看起来合理”的惩罚。

## 6. PPO到底学到了什么

训练时，策略常用高斯分布采样动作：

```math
a_t\sim\pi_\theta(\cdot\mid o_t).
```

环境执行动作，返回奖励和下一观测。critic估计未来回报，GAE提供优势估计，PPO用新旧动作概率之比约束更新幅度：

```math
\rho_t(\theta)=\frac{\pi_\theta(a_t\mid o_t)}{\pi_{\theta_{\mathrm{old}}}(a_t\mid o_t)},
```

```math
L(\theta)=\mathbb{E}_{t}\left[\min\left(\rho_t(\theta)\hat{A}_t,
\mathrm{clip}(\rho_t(\theta),1-\epsilon,1+\epsilon)\hat{A}_t\right)\right].
```

与手写PPO相同，旧log-prob、优势和return target要在这一轮优化前冻结。训练循环大体是“并行采样→GAE→多轮minibatch更新→继续采样”。

奖励好的动作序列在优化中获得支持，策略逐渐形成协调行为。它可能学出某种步态，但不意味着内部显式存储了“先左脚再右脚”的人类规则。如果任务加入相位或运动参考，那么它们是设计者提供的额外结构，需要说明。

训练动作有随机性；确定性评估常用均值动作，但仍可能保留初始化与观测噪声。二者回报不能不加说明地直接比较。

## 7. 终止和截断在人形上尤其容易混淆

真正失败，例如身体跌落并触发终止，通常不应从下一回合状态bootstrap。时间到达上限属于截断时，需要按算法实现用正确的末状态价值处理，不能把自动reset后的新状态当作旧回合末状态。

若机器人只是短暂膝盖触地，但任务没有将其列为终止body，可能不会报告“摔倒”。反过来，误把合法足部接触设为终止条件，会让正常步行无法继续。

所以先读任务定义，再解释终止率。“0次终止”只意味着没有触发该判定，不自动等于没有拖脚、跳步或不自然姿态。

## 8. 哪些指标一起看

- 训练回报和分项奖励：解释优化方向。
- 独立评估的速度/角速度误差：解释任务完成程度。
- 每回合长度和终止原因：解释生存与失败。
- 接触、倾角、高度、动作变化：解释运动方式。
- KL、clip fraction、entropy、critic误差：排查优化是否异常。

PPO loss不必单调下降，也不能用它给两个不同奖励配置的机器人排运动质量。视频不能代替指标，指标也不能代替运动过程检查。

## 9. 自测

1. 为什么修改动作缩放可能比修改学习率更直接地改变运动？
2. 为什么actor和critic维数不同时，不应马上认为代码出错？
3. 为什么一个“站着不动”的策略可能得到不错的部分奖励？
4. 为什么固定训练seed仍不保证GPU仿真逐帧完全相同？
5. 短训练保存/加载通过后，是否可以声称模型已经学会行走？

参考要点：动作缩放改变控制输入；critic可能利用特权信息；任务奖励存在取舍；后端并行数值运算与随机过程需要单独考虑；工程链路和行为能力是两个验收层次。
