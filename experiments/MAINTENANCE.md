# 实验维护约定

用户要求在推进实验时持续清理失败和无用实验。每轮结束、确认任务不再运行后，顺手核对本地和服务器的可清理内容；不创建周期后台清理任务。

- 活动任务的运行包、当前对照模型和未分析结果不清理。
- 失败训练不等于无用证据：保留正式指标、配置、源码快照、结论及最终模型；明确标记负结果，不从统计中删失败回合。
- 已结束任务的重复运行包、失败轮次多余中间检查点，先压缩归档，逐文件核验 SHA256，记录原相对路径后移出活动目录。初始和最终 checkpoint 保留原位以兼容分析脚本。
- 归档需要恢复才能读取的路径，在清理清单中保留；不随意重新编号既有实验，避免破坏历史引用。
- 可再生成媒体按需求清理；保留展示关键异常/对照的证据。删除整类正式实验或不可恢复的最终模型前重新判断具体范围，不把“失败”自动视为可永久删除。

恢复依据：每端 archives/maintenance_001/manifest.json 与 completed_contexts_and_intermediate_checkpoints.zip。归档逐文件哈希校验通过后才删除原副本；archives目录本身不自动清空。

## maintenance_002（2026-10-18）

确认服务器没有活动任务后，两端各归档7个已完成的重复运行包、48个文件。压缩后逐文件核验SHA256再移出contexts/.task_context；全部正式模型、检查点、失败轨迹和导出结果保持原位。记录分别位于本地和服务器archives/maintenance_002/manifest.json，压缩包为completed_contexts.zip。历史文档的contexts路径现需从此归档恢复，或使用各实验目录中的源码快照。

GitHub只发布维护中的源码、文档、冻结配置和紧凑验收/诊断JSON；原始轨迹、训练日志、二进制模型、视频和复现ZIP保留在本地及NAS。忽略规则只控制提交范围，不删除原件。详见experiments/ARTIFACTS.md。
